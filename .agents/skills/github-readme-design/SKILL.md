# GitHub README Design

把项目 README 做成清晰、克制、有设计感的产品入口。先让读者知道「是什么、适合谁、怎么开始」，再提供深入资料。默认使用中文正文，保留产品原名；遵循用户指定语言。

## 1. 确定范围与证据

- 读取仓库默认分支、README、适用的 AGENTS.md、目录、许可证、最新 Release、安装/构建脚本和现有截图。
- 多仓库任务先列出候选。没有更明确要求时优先活跃公开项目，不把私有资料引入公开页面。
- 尊重仓库中的用户修改；获取写入前最新 SHA，避免覆盖并发更新。
- 为平台、运行时、安装命令、功能、数据行为、性能和来源分别记录证据。
- 不从仓库名字推断功能，不将规划当成功能，不虚构 star 数、用户量、速度、兼容性、CI 状态或官方关系。
- 空仓库只介绍已确定的目标与当前状态，不伪造截图、下载和完成度。

## 2. 参考与选择

读取 2–3 个与项目类型相近、已有广泛使用的项目 README，记录 URL、日期及可迁移结构。使用 [references.md](references.md) 作为候选来源；重新读取后再引用，不把历史观察称为当前热门榜单。

借鉴信息层级与可读性，不复制对方的品牌、图标、截图或营销文案。说明为什么选用某个结构，而不是把所有模块照搬。

## 3. 信息结构

按需要选用以下顺序，不必机械填满：

1. 简短产品类别（可选）。
2. 产品名：一个 H1。
3. 一句中文定位：用户对象 + 具体动作/结果；可附一句简短英文描述。
4. 一个主要行动：下载、在线体验或快速安装。最多三个辅助入口。
5. 一行经核实的平台、运行时、许可信息。
6. 一张真实产品主图，配有描述性的 alt；已有深浅色图时使用 picture。
7. 三个互不重复的用途，用短列表或简单三列表格呈现。
8. 快速开始：可执行步骤、必要依赖、预期结果、关键兼容限制。
9. 常用操作、数据与权限说明。
10. 深入文档、构建、验证、贡献和来源许可。

原作者署名、关键兼容性限制和独立项目声明应保持易见。性能历史、定位细节等次要信息可以放入 details；不要折叠首次使用必须知道的内容。

## 4. 视觉规则

- 风格：居中首屏、左对齐正文、短段落、适度留白、清晰标题层级。
- 只使用 GitHub 可渲染 Markdown 与少量 HTML：p、h1、sub、strong、a、img、picture、source、details、summary。
- 不依赖 style、script、iframe、自定义字体或 CSS 布局；README 不是任意 HTML 网页。
- 避免超大装饰横幅、密集 emoji、徽章墙、访问计数、星标动画和无内容占位区。
- 徽章只有表达真实状态时才使用；首屏优先文本和真实产品画面，避免第三方服务依赖。
- 图片使用仓库内相对路径。主图宽度适应容器，避免固定大宽度造成窄屏溢出。
- 深浅色图片表达同一内容。缺少主题图时使用能在两种背景上辨认的现有素材。
- 不生成虚假产品界面来冒充截图。没有截图时可使用明确标注的示意图，或先采用文字版。
- 表格最多三列用于用途展示；长说明使用段落或列表，不强迫所有内容进入表格。
- 导航锚点必须与真实标题匹配；HTML 块和 Markdown 之间保留空行。

## 5. 保留事实，压缩阅读负担

优先重排现有可靠内容。每个模块只回答一个问题。保留运行要求、命令、快捷键、隐私边界、测量条件、版本、作者归属和许可证链接。

性能数字必须带环境、方法、日期/版本和来源；不把 UI 心跳当屏幕帧率，不把有限设备测试当全平台保证。原有历史验证不能写成此次重新运行的验证。

## 6. 实施与验证

- 在独立工作目录生成完整文件并检查差异，再写入已授权目标。
- 检查所有本地链接和图片路径存在；检查锚点、代码围栏、HTML 标签配对。
- 验证主要下载入口及 Release 资产名称、依赖版本和命令路径。
- 有浏览器或渲染器时检查 GitHub 实际渲染，覆盖深/浅色和窄屏；只能静态检查时明确说明，不宣称视觉验收完成。
- 与旧版逐项核对事实、限制和署名，避免为美观删掉必要信息。
- 仅文档排版变更不需要跑无关的应用测试；不得将历史测试描述为本次执行。
- 发布方式遵守用户授权与仓库规则；可直接写入已授权分支，或使用分支/PR。用户未要求时不顺带改可见性、权限、默认分支或删除仓库。
- 写入后重新读取核对结果；SHA 冲突时重新读取并融合，不强制覆盖。

## 7. 交付

提供已更新页面或 PR 链接，简述信息结构、保留的重要限制、完成的检查和未完成的检查。如果还要求打包 skill，提供整个目录，保持 SKILL.md 的 YAML name/description 和参考文件有效。

推荐目录：

```text
.agents/skills/github-readme-design/
├── SKILL.md
└── references.md
```

将整个目录复制到支持 Agent Skills 的工具的技能目录；具体安装位置以该工具文档为准。仓库中存在文件不等于所有客户端都已经安装或启用。

调用示例：「使用 github-readme-design，重设计这个仓库的 README；保留真实功能、安装步骤和来源署名，完成后验证链接并按已有授权提交。」
